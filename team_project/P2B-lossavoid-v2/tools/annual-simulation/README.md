# 年間調理順シミュレーション

Oracleの注文データやKDSの調理状態を書き換えない、オフラインの負荷試験です。

```powershell
node tools/annual-simulation/run.cjs "C:\Users\cybor\Documents\Codex\2026-06-29\files-mentioned-by-the-user-c\outputs\annual-kitchen-report-2026"
node --test tests/annual-kitchen-simulation.test.cjs
```

出力先の `report.html` をブラウザで開くと、通年・時間帯のグラフと表を見られます。
CSVには全政策の比較、365日、4,380時間、最速政策の注文・商品ごとの時刻を保存します。

## 前提

- 2026年の365日、毎日11:00-23:00に注文が到着。注文は23:00で停止し、残務は最後まで処理します。
- 時間帯別の平均注文数は `engine.cjs` の `HOURS` に設定。週末・日ごとの変動を加えたポアソン過程です。実店舗の年間POS実績ではありません。
- 70品のメニューマスタと、50行の注文詳細から作った補助的な人気度を `menu-snapshot.json` に固定しています。人気度には平滑化を加えています。
- 調理の基準時間は既存の `kitchen-scheduler.js` の `resolveRecipe` から取得し、商品ごとに0.8-1.2倍の変動と一部遅延を与えています。
- 上下オーブンは2枚ずつ23秒/43秒の投入間隔。他設備の能力、2名の持出し担当と移動時間は仮定です。複数周回料理の追加投入・鉄板占有とオーブン前後の手作業は厳密には再現していません。
- 同じ乱数の365日をすべてのルールへ適用。FIFO・短時間/長時間優先・伝票優先など135通りを比較し、良い候補の周辺を細分化して、改善が止まるまで探索します。さらに客足1.5倍の別の365日で感度を確認します。
- 「最速」は試した候補の中での平均全品提供時間が最短という意味です。最適解や実店舗の予測値を保証しません。
- 「提供差重視」は最速より平均全品提供が15秒以内、温製品の完成後待機がFIFOより24秒以内の増加という条件で、同一伝票の提供差を最小化した候補です。これらは品質・食品安全の認定閾値ではありません。

## 出力

- `report.html`: 通年、時間帯、比較表、感度分析の閲覧用レポート
- `summary.json`: 全前提と主要指標
- `policy-comparison.csv`: 全候補の比較
- `stress-150pct.csv`: 客足1.5倍の追加比較
- `daily-365.csv`: 日別の時間指標
- `hourly-4380.csv`, `hourly-profile.csv`: 日×時間帯および平均時間帯の指標
- `order-times.csv`, `item-times.csv`: 最速候補の全注文・全商品の時刻

注文から全品提供までの平均だけでなく、95パーセンタイル、同一伝票の提供差、完成後の温製品待機、閉店後の残務を確認してください。実運用へ反映する前に、調理・持出し・客足の実測値と、同時調理設備の能力を置き換える必要があります。
